### BUG-01　查询不存在的用户详情抛空指针异常并泄露技术细节

- **模块**：用户管理　|　**严重**：严重　|　**优先级**：高　|　**类型**：代码缺陷/信息泄露　|　**状态**：待修复
- **关联用例**：USER-007
- **测试环境**：RuoYi-Vue 前后端分离版；后端 http://localhost:8080；MySQL 8.0
- **复现步骤**：

  1. 以 admin 登录获取 Token
  2. 请求 GET /system/user/99999（不存在的 userId）

- **预期结果**：返回友好提示「用户不存在」或 HTTP 404
- **实际结果**：HTTP 200 / code=500，msg=Cannot invoke "com.ruoyi.common.core.domain.entity.SysUser.getRoles()" because "sysUser" is null
- **影响范围**：1) 前端只能展示「操作失败」，用户无法判断是数据不存在还是系统故障；2) 错误信息直接暴露后端 Java 类名与调用链语义，存在信息泄露风险，可被用于探测技术栈
- **修复建议**：在 SysUserServiceImpl.selectUserById 中增加空值判断，为空时抛出 ServiceException("用户不存在") 或返回统一业务码；同时全局异常处理器对外屏蔽 Java 内部异常细节
- **证据来源**：testcases/test_bugs.py::test_bug_user_detail_nullpointer（自动化断言固化）

### BUG-02　新增/重置密码未校验长度，4 位弱密码可成功写入

- **模块**：用户管理　|　**严重**：严重　|　**优先级**：高　|　**类型**：安全缺陷/校验缺失　|　**状态**：待修复
- **关联用例**：USER-014、USER-015
- **测试环境**：同上
- **复现步骤**：

  1. POST /system/user 传 password="1234"
  2. POST /system/user 传 password=21 位字符串
  3. PUT /system/user/resetPwd 将 userId=3 密码改为 "1234"

- **预期结果**：密码长度应限定 5~20 位，越界返回校验失败
- **实际结果**：三次请求均 code=200，msg=操作成功，弱密码/超长密码均成功入库
- **影响范围**：前端虽有长度限制，但攻击者绕过前端直接调用接口即可写入 4 位弱口令，账户存在被暴力破解风险；违反等保对密码强度的要求
- **修复建议**：在实体 SysUser.password 上补充 @Size(min=5,max=20) 校验注解，并在新增、重置密码、修改密码三处入口统一校验；建议同时增加复杂度校验（字母+数字）
- **证据来源**：探针 _probe_api3.py / _probe_api5.py 实测记录

- **测试环境**：同上

  1. 分别请求 /system/role/99999、/system/menu/99999、/system/dept/99999、/system/post/99999、/system/dict/type/99999、/system/config/99999
