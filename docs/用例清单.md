## 三、用例设计说明

**测试范围**：覆盖 RuoYi-Vue 后台管理系统 8 大业务模块（登录鉴权、用户、角色、菜单、部门、岗位、字典、参数），共 41 个接口。在功能测试之外，补充了接口级垂直越权（未认证 401 / 低权限 403）专项、SQL 注入防护专项、以及基于 MySQL 的数据一致性校验。

**用例设计方法**：综合运用等价类划分、边界值分析、错误推测、场景法、状态迁移与数据驱动：
  · 等价类/边界值：分页参数（pageNum/pageSize 取 0、负数、越界、超大值）、字符串长度（昵称 30/31、账号 30/31、密码 4/21、手机号 11/13）
  · 错误推测：详情接口查不存在 ID、非法外键（deptId/roleIds/parentId）、非数字手机号、含空格与特殊字符的账号
  · 场景法：新增-查询-删除全链路；构造父节点+子节点验证级联删除保护
  · 数据驱动：@pytest.mark.parametrize 覆盖多组分页与多接口越权矩阵
  · 状态迁移：用户/角色启用停用状态切换
  · 一致性校验：接口返回与数据库落库双向比对

**自动化实现**：Python 3.10 + pytest + requests，配合 Redis 读取验证码明文实现「万能验证码」自动登录，统一请求层（common/api_client.py）集中管理 base_url、超时、鉴权头与 401 自动重登，pytest fixture 会话级共享 Token（整个测试会话只登录一次），allure/pytest-html 生成可视化报告。当前 33 条自动化用例（70 个参数化实例），100% 通过。

**缺陷挖掘方式**：不依赖人工点界面，而是编写 5 轮接口探针脚本（_probe_api.py 与 _probe_api2~5.py，位于 probe/ 目录），对每条待写入文档的行为做真实请求实测，以「实测响应」作为用例的「实际结果」与缺陷证据，保证文档数据 100% 可复现、不臆造。

**执行环境**：Windows 11；Docker 部署 RuoYi（backend:8080、frontend:80、redis:6380、mysql:3306）；Python 3.10.11；pytest 9.1.1；MySQL 8.0；JDK 17。

**结果概览**：共设计执行用例 {total} 条，其中通过 {passed} 条、失败（暴露缺陷）{failed} 条；共登记缺陷 {bugcount} 个（严重 5 / 一般 5 / 轻微 2）。失败用例数多于缺陷数，是因为同一缺陷（如 BUG-02 密码长度校验缺失）会在新增、重置密码等多个入口重复暴露，已在关联用例字段中标注。所有失败用例均对应已登记缺陷，失败即缺陷证据，而非用例本身写错。
